# Nava P2P — Android offline messenger foundation

این مخزن، شروع یک اپلیکیشن **Native Android** با هدف پیام‌رسانی محلی و غیرمتمرکز است؛ وب‌اپ یا WebView نیست.

## وضعیت واقعی این نسخه

نسخه 0.1 یک نمونه اولیه قابل توسعه است:
- اپلیکیشن Native با Kotlin
- کشف همتاها در یک شبکه IP محلی از طریق UDP broadcast
- کشف دستگاه‌های Wi-Fi Direct با `WifiP2pManager`
- درخواست اتصال Wi-Fi Direct به دستگاه انتخاب‌شده
- ارسال متن آزمایشی TCP از کلاینت Wi-Fi Direct به آدرس گروه‌دار
- دریافت و ارسال متن آزمایشی از طریق TCP در شبکه محلی
- مجوزهای پایه Wi-Fi و Bluetooth در Manifest

**این نسخه هنوز معادل Briar نیست و نباید برای پیام خصوصی واقعی استفاده شود.**
- پیام‌ها هنوز رمزنگاری سرتاسری ندارند.
- UDP discovery ممکن است در بعضی روترها/هات‌اسپات‌ها مسدود باشد.
- Wi-Fi Direct اکنون کشف و اتصال اولیه دارد و از TCP برای نمونه انتقال پیام استفاده می‌کند. این مسیر روی همه مدل‌های گوشی آزمایش نشده است.
- Bluetooth هنوز فقط مجوزهای پایه و نقطه توسعه دارد؛ BLE discovery و GATT messaging باید در مرحله بعد تکمیل شوند.
- چت پایدار، تاریخچه امن، گروه، فایل، احراز هویت هویت‌ها و اجرای پس‌زمینه هنوز پیاده‌سازی نشده‌اند.
- APK در این محیط ساخته نشده است؛ این مخزن سورس پروژه Android Studio است.

## معماری هدف

`Peer Identity / Trust`  
↳ `Transport Manager`  
↳ Wi-Fi LAN (UDP discovery + TCP)  
↳ Wi-Fi Direct (P2P group + socket transport)  
↳ Bluetooth LE (discovery / rendezvous) + Bluetooth Classic RFCOMM (data fallback)  
↳ `Encrypted Message Protocol` (X25519 key agreement + authenticated encryption)  
↳ `Local encrypted database`

ارتباط‌ها باید مستقل از transport باشند؛ برنامه ابتدا peer را پیدا می‌کند، سپس بهترین مسیر قابل دسترس را انتخاب می‌کند. هیچ سرور مرکزی یا حساب ابری لازم نیست. هر گوشی می‌تواند همزمان نقش کشف‌کننده، فرستنده و گیرنده را داشته باشد.

## ساخت APK

### Android Studio
1. پوشه پروژه را باز کنید.
2. JDK 17 و Android SDK Platform 35 نصب باشد.
3. Gradle Sync را انجام دهید.
4. از مسیر **Build > Build APK(s)** خروجی بگیرید.

خروجی معمولاً:
`app/build/outputs/apk/debug/app-debug.apk`

### Termux
بیلد کامل Android از داخل Termux روی خود گوشی معمولاً به Android SDK/Build Tools و فضای ذخیره‌سازی قابل توجه نیاز دارد. روش مطمئن‌تر:
- سورس را به GitHub push کنید.
- از GitHub Actions برای ساخت APK استفاده کنید.
- APK را از Artifacts دریافت کنید.

## GitHub Actions

فایل workflow نمونه در `.github/workflows/android.yml` قرار دارد. پس از push، تب Actions را باز کنید و artifact با نام `nava-debug-apk` را دریافت کنید.

## اجرای آزمایشی
برای تست LAN، دو گوشی را به یک Wi-Fi وصل کنید، APK را روی هر دو نصب کنید، مجوزهای Nearby devices را بدهید و «جست‌وجوی دستگاه‌های اطراف» را بزنید. سپس «پیام آزمایشی» را انتخاب کنید.

## نقشه راه ضروری پیش از انتشار
1. تکمیل مدیریت چرخه اتصال Wi-Fi Direct، reconnect و انتخاب نقش گروه.
2. افزودن BLE advertising/scanning و GATT برای انتقال داده.
3. طراحی پروتکل handshake و احراز هویت با QR/fingerprint.
4. رمزنگاری سرتاسری با کتابخانه معتبر و آزمون‌شده؛ از پیاده‌سازی رمزنگاری دست‌ساز خودداری شود.
5. پایگاه داده رمزنگاری‌شده، صف پیام آفلاین و رسید تحویل.
6. foreground service و مدیریت محدودیت‌های باتری اندروید.
7. آزمون چندسازنده‌ای و آزمون امنیتی مستقل.

## امنیت و محدودیت شبکه
Wi-Fi Direct معمولاً خودش یک گروه محلی ایجاد می‌کند و لزوماً به روتر یا اینترنت نیاز ندارد. Bluetooth و Wi-Fi Direct در نسخه‌های مختلف Android نیازمند مجوزهای runtime متفاوت‌اند. بعضی سازندگان محدودیت‌های پس‌زمینه یا کشف دستگاه دارند.


## نسخه 0.3.0 — لوگو و مدیریت
- آیکون لانچر و آیکون گرد برنامه در منابع `mipmap-*` موجود است و در Manifest ثبت شده است.
- تصویر برند اصلی در `assets/nava-brand-logo.png` قرار دارد.
- دکمه «بخش مدیریت» به صفحه اصلی اضافه شده است.
- رمز مدیریت به‌صورت متن خام داخل سورس ذخیره نشده؛ فقط salt و خروجی مشتق‌شده PBKDF2-HMAC-SHA256 با 310,000 دور در برنامه قرار دارد.
- رمز از داخل برنامه قابل تغییر نیست و قابلیت تغییر/بازیابی رمز ارائه نشده است.

**محدودیت امنیتی مهم:** چون برنامه کاملاً آفلاین و بدون سرور است، کنترل دسترسی سمت کلاینت قابل مهندسی معکوس یا patch شدن است. برای مقاومت در برابر دستکاری APK نمی‌توان صرفاً با یک رمز ثابت درون APK تضمین مطلق داد. برای امنیت واقعی پیام‌رسان، هویت و رمزنگاری پیام‌ها باید مستقل از این قفل مدیریتی طراحی و آزمون شوند.
